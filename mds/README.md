# Мультимодальная диспетчерская система

Программная система для согласования и диспетчеризации маршрутов беспилотных транспортных средств четырёх типов в условиях городской среды с разнородными препятствиями.

## Назначение

Система моделирует работу городского диспетчерского центра, который принимает заявки на маршруты от доверенных клиентов (магазинов, аптек, служб доставки) и проверяет их на:

- **геометрическую проходимость** — пересечение маршрута с активными препятствиями (лестницы, перекопы, запретные зоны, мелководье);
- **совместимость с параметрами транспорта** — высота, осадка, ширина, масса;
- **пропускную способность коридора** — количество уже согласованных маршрутов на тех же сегментах в пересекающемся временном окне.

Каждая заявка получает одно из решений: `approved`, `approved_with_changes`, `rejected`, `pending`.

## Возможности

- Поддержка **4 сред перемещения**: тротуар, автодорога, воздушное пространство, акватория.
- Учёт **временных окон активности** препятствий (например, разводной мост работает по расписанию).
- **Параметрические ограничения** транспорта (`max_height`, `max_draft`, `min_width` и др.).
- **Карта занятости коридоров** (`OccupancyMap`) с послойным хранением занятий сегментов.
- Ведение **журнала заявок** и списка согласованных маршрутов.
- **Регистрация клиентов** — только доверенные источники могут отправлять заявки.
- Набор **визуализаций**: карта города, диаграмма Ганта, аналитика по статусам и типам транспорта.
- Демонстрационный сценарий с 5 заявками, покрывающими все типы транспорта.

## Быстрый старт

```bash
python demo.py
```

Скрипт:

1. создаёт карту с 8 препятствиями;
2. регистрирует двух клиентов (`pizza_shop`, `pharmacy`);
3. отправляет 5 заявок — по одной на каждый тип транспорта (ровер дважды);
4. печатает решения по каждой заявке;

   - `city_map.png` — карта с препятствиями и маршрутами;
   - `gantt.png` — временная диаграмма согласованных маршрутов;
   - `analytics.png` — аналитика по типам и статусам.

## Описание модулей

### `models.py`

Определяет предметную модель:

```python
class TransportType(Enum):
    SIDEWALK_ROVER = "sidewalk_rover"
    AUTONOMOUS_CAR = "autonomous_car"
    AERIAL_DRONE   = "aerial_drone"
    WATER_VESSEL   = "water_vessel"
```

`RouteRequest` содержит `vehicle_params` — словарь с параметрами, зависящими от типа транспорта:

| Тип | Параметры |
|-----|-----------|
| `sidewalk_rover` | `width`, `max_slope` |
| `autonomous_car` | `height`, `mass` |
| `aerial_drone` | `max_alt`, `payload` |
| `water_vessel` | `draft`, `height` |

### `city_map.py`

`Obstacle` описывает препятствие:

- `transport_types` — список сред, к которым оно относится;
- `geometry` — shapely-геометрия (`Polygon`, `LineString`, `Point.buffer(...)`);
- `active_from` / `active_to` — временное окно активности (`datetime.time`);
- `severity` — `full_block` / `slowdown` / `restriction`;
- `params` — например `{"max_height": 3.0}` или `{"min_width": 0.8}`.

Метод `get_active_obstacles(transport_type, at_time)` возвращает препятствия, активные в указанный момент.

### `checker.py`

`RouteChecker.check()` выполняет три шага:

1. **Геометрия.** Строит `LineString` по путевым точкам и проверяет пересечение с каждым активным препятствием (`_intersects`).
2. **Параметры.** Если в `obstacle.params` есть `max_height` / `max_draft` / `min_width`, сравнивает с `vehicle_params` заявки.
3. **Пропускная способность.** Запрашивает у `OccupancyMap` загрузку сегментов на момент отправления и сравнивает с лимитом `_max_capacity()`.

Лимиты по средам:

| Среда | `_max_capacity` |
|-------|-----------------|
| `sidewalk_rover` | 2 |
| `autonomous_car` | 3 |
| `aerial_drone` | 4 |
| `water_vessel` | 1 |

### `occupancy.py`

`OccupancyMap` хранит по слоям (среда) словарь `сегмент → список занятий`. Ключ сегмента нормализуется: координаты округляются до 0.1, пара точек сортируется (порядок не важен).

```python
def _segment_key(self, p1, p2) -> str:
    a = (round(p1.x, 1), round(p1.y, 1))
    b = (round(p2.x, 1), round(p2.y, 1))
    return f"{min(a, b)}__{max(a, b)}"
```

`get_load(...)` возвращает максимальную загрузку по всем сегментам маршрута в окне `[at_time, at_time + 20 мин]`.

### `dispatcher.py`

`Dispatcher.submit_request()` — основной вход системы:

1. проверяет, что клиент зарегистрирован;
2. сохраняет заявку в журнал `self.requests`;
3. создаёт `RouteChecker` для нужной среды;
4. при одобрении создаёт `ApprovedRoute` с окном `[departure_time, +30 мин]` и регистрирует в `OccupancyMap`;
5. возвращает словарь `{request_id, status, reason, conflicts}`.

## Модель препятствий

Препятствие характеризуется:

- **геометрией** — `Polygon`, `LineString`, `Point.buffer(...)`;
- **средой** — список `transport_types`;
- **временем** — `active_from`, `active_to`;
- **серьёзностью** — `full_block`, `slowdown`, `restriction`;
- **параметрами** — числовые ограничения.

Примеры из `demo.py`:

```python
city.add_obstacle(Obstacle(
    obstacle_id="drawbridge_1",
    transport_types=["water_vessel"],
    geometry=Point(60, 50).buffer(3),
    active_from=time(14, 0), active_to=time(14, 20),
    severity="restriction",
    params={"max_height": 3.0,
            "schedule": [("02:00", "02:30"), ("14:00", "14:20")]}
))
```

## Логика принятия решений

| Условие | Решение |
|---------|---------|
| Конфликтов нет | `APPROVED` — «Маршрут свободен» |
| Есть конфликты, для каждого есть рекомендация | `APPROVED_WITH_CHANGES` |
| Есть конфликты без рекомендации | `REJECTED` |
| Клиент не зарегистрирован | `REJECTED` (в `Dispatcher`) |

Рекомендации формируются в `_make_recommendation`:

- `full_block` → «Объезд препятствия X»;
- `slowdown` → «Замедление из-за X»;
- `restriction` → «Ограничение: X (изменить маршрут или время)».

## Визуализация

### `visualize.py` — карта города

- препятствия заливаются цветом по `severity` (чёрный — `full_block`, оранжевый — `slowdown`, серый — `restriction`);
- согласованные маршруты рисуются цветом типа транспорта с маркерами путевых точек;
- легенда дедуплицируется по подписям;
- результат сохраняется в `city_map.png`.

Палитра:

| Тип | Цвет |
|-----|------|
| `sidewalk_rover` | `#2ecc71` (зелёный) |
| `autonomous_car` | `#3498db` (синий) |
| `aerial_drone` | `#e74c3c` (красный) |
| `water_vessel` | `#9b59b6` (фиолетовый) |

### `gantt.py` — диаграмма Ганта

Горизонтальные полосы по времени для каждого маршрута, окрашенные по типу транспорта, с подписью `route_id`. Сохраняется в `gantt.png`.

### `analytics.py` — аналитика

Две диаграммы на одном полотне:

1. круговая — распределение согласованных маршрутов по типам транспорта;
2. столбчатая — распределение заявок по статусам.

Сохраняется в `analytics.png`.

## Расширение системы

### Добавить новый тип транспорта

1. Добавьте значение в `TransportType` (`models.py`).
2. Добавьте слой в `OccupancyMap.layers` (`occupancy.py`).
3. Добавьте лимит в `RouteChecker._max_capacity` (`checker.py`).
4. Добавьте цвет в `COLORS` (`visualize.py`).

### Добавить новое препятствие

```python
city.add_obstacle(Obstacle(
    obstacle_id="new_obstacle",
    transport_types=["autonomous_car"],
    geometry=Polygon([(10, 10), (20, 10), (20, 20), (10, 20)]),
    active_from=time(9, 0), active_to=time(18, 0),
    severity="slowdown",
    params={"avg_delay": 5}
))
```

### Изменить правило проверки

Переопределите `RouteChecker._intersects` или `_make_recommendation` — они изолированы и не зависят от диспетчера.

### Подключить реальный источник препятствий

Замените наполнение `CityMap` на загрузку из внешнего API — интерфейс `add_obstacle` / `get_active_obstacles` останется неизменным.
