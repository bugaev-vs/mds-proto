## Наземный автономный транспорт делится на два подтипа

| Аспект        | Тротуарный ровер (доставщик)                           | Беспилотный автомобиль                        |
| ------------- | ------------------------------------------------------ | --------------------------------------------- |
| Среда         | Тротуары, пешеходные зоны                              | Проезжая часть, дороги                        |
| Скорость      | 5–10 км/ч                                              | 40–60 км/ч                                    |
| Препятствия   | Пешеходы, коляски, велосипеды, урны, лестницы, пандусы | Другие авто, светофоры, разметка, перекрёстки |
| Регулирование | Приоритет пешехода                                     | ПДД, приоритет по знакам                      |
| Габариты      | Малые (0.5–1 м)                                        | Крупные (4–5 м)                               |
| Маршрут       | Граф тротуаров и переходов                             | Граф дорог                                    |
| Конфликты     | Толпа, узкий тротуар, вход в подъезд                   | Полосы, перекрёстки, обгон                    |

Ключевое: **это два разных графа**. Тротуарный ровер не может выехать на проезжую часть (кроме специальных переходов), а автомобиль — на тротуар. Диспетчер должен это учитывать.

---

## Почему это важно для проекта

1. **Реалистичность.** В реальных городах уже есть и тротуарные доставщики (Яндекс Ровер, Starship), и беспилотные такси. Они не конкурируют, а дополняют друг друга.
2. **Уникальные препятствия.** У тротуарного ровера свой набор проблем, которого нет у автомобиля: лестницы, узкие проходы, скопления людей, входные группы.
3. **Разная логика согласования.** Автомобиль согласуется по полосам и перекрёсткам, ровер — по тротуарам и переходам.

## Классификация автономного транспорта

```
АВТОНОМНЫЙ ТРАНСПОРТ
│
├── НАЗЕМНЫЙ
│   ├── Тротуарный ровер (доставщик)
│   │   └── среда: тротуары, пешеходные зоны
│   └── Беспилотный автомобиль
│       └── среда: проезжая часть
│
├── ВОЗДУШНЫЙ
│   └── Дрон
│       └── среда: воздушные коридоры
│
└── ВОДНЫЙ
    └── Катер / баржа
        └── среда: фарватеры, шлюзы
```

Итого — **четыре модуля проверки**, но два из них работают по графам с разными правилами. Плюс подобной структуры: архитектура остаётся модульной, а сложность программ растёт линейно и зависит от требований по отдельным видам АТ.

## Уникальные препятствия тротуарного ровера

| Препятствие              | Как моделируется                  | Влияние                   |
| ------------------------ | --------------------------------- | ------------------------- |
| **Лестница**             | Точка с флагом `stairs`           | Полный запрет проезда     |
| **Пандус**               | Точка с флагом `ramp`             | Разрешено, но медленнее   |
| **Узкий тротуар**        | Ребро с `min_width`               | Ровер шире — объезд       |
| **Скопление пешеходов**  | Полигон с динамической плотностью | Замедление или ожидание   |
| **Входная группа**       | Точка с состоянием `free/busy`    | Ожидание или другой вход  |
| **Велосипедная дорожка** | Ребро с приоритетом велосипедов   | Ограничение скорости      |
| **Переход через дорогу** | Точка с расписанием светофора     | Ожидание                  |
| **Лужа / гололёд**       | Полигон с сезонным флагом         | Замедление или объезд     |
| **Собака на поводке**    | Динамическое препятствие          | Объезд в реальном времени |

Пример структур:
```python
stairs = {
    "type": "stairs",
    "position": (35, 42),
    "severity": "full_block"       # ровер не пройдёт
}

narrow_sidewalk = {
    "type": "narrow",
    "segment": [(50, 20), (60, 20)],
    "min_width": 0.8,              # метров
    "note": "Ровер шириной 0.9 м не пройдёт"
}

crowd = {
    "type": "crowd",
    "polygon": [(70, 30), (75, 30), (75, 35), (70, 35)],
    "density": "high",             # low / medium / high
    "active_from": "12:00",
    "active_to": "14:00"           # обеденный час
}

entrance = {
    "type": "entrance",
    "position": (80, 60),
    "status": "busy",              # free / busy
    "alternative": (82, 60)        # соседний вход
}
```

## Сравнение двух наземных модулей

| Проверка  | Тротуарный ровер         | Беспилотный автомобиль    |
| --------- | ------------------------ | ------------------------- |
| Граф      | Тротуары                 | Дороги                    |
| Запреты   | Лестницы, узкие проходы  | Перекопы, закрытые полосы |
| Задержки  | Пешеходы, входные группы | Светофоры, пробки         |
| Приоритет | Пешеход всегда прав      | ПДД, знаки                |
| Скорость  | Низкая                   | Высокая                   |
| Конфликты | Толпа                    | Полосы, перекрёстки       |
| Особое    | Переход через дорогу     | Парковка, остановки       |

Обе модели используют **граф**, но с разными наборами рёбер и правил. Это значит, что код проверки можно **переиспользовать** — отличается только конфигурация.

## Единая карта занятости — четыре слоя

```python
occupancy = {
    "sidewalk": {                  # тротуарные роверы
        "segment_A_B": [
            {"route_id": "R-001", "time": ("14:00", "14:15"), "vehicle": "rover_01"}
        ]
    },
    "road": {                      # беспилотные автомобили
        "lane_North_1": [
            {"route_id": "R-002", "time": ("14:00", "14:08"), "vehicle": "car_01"}
        ]
    },
    "air": {                       # дроны
        "corridor_1_alt60": [
            {"route_id": "R-003", "time": ("14:00", "14:20"), "vehicle": "drone_01"}
        ]
    },
    "water": {                     # катера
        "fairway_North": [
            {"route_id": "R-004", "time": ("14:00", "14:45"), "vehicle": "boat_01"}
        ]
    }
}
```

Важно: **тротуар и дорога — разные слои**. Ровер не мешает автомобилю, но оба находятся «на земле». Это разделение позволяет точно моделировать конфликты внутри каждой среды.

## Уникальные сценарии с тротуарным ровером

Кейсы для демонстрации:

1. **Ровер не может пройти из-за лестницы** → рекомендация объезда через пандус.
2. **Узкий тротуар** → ровер шире прохода, нужен альтернативный путь.
3. **Скопление пешеходов в обед** → МДС рекомендует сдвинуть доставку на 15-20 минут.
4. **Входная группа занята** → МДС предлагает соседний вход.
5. **Переход через дорогу** → ровер ждёт зелёный сигнал, система учитывает задержку.
6. **Пересечение с автомобилем на переходе** → диспетчер координирует оба транспорта, чтобы не было конфликта.

Последний кейс наиболее сложный: **ровер и автомобиль движутся по разным графам, но пересекаются на переходах**. МДС должна согласовать оба маршрута, чтобы они не встретились на переходе в одно время. Это уже **межсредовое взаимодействие** — аргументация необходимости внедрения МДС на защите проекта.

---

## Что это даёт проекту

1. **Максимальная реалистичность.** Ты покрываешь все актуальные типы городской беспилотной доставки: роверы, автомобили, дроны, катера.
2. **Глубина проработки.** Внутри одной среды (земля) различаются подтипы АТ с разными правилами — это уровень реальных диспетчерских.
3. **Межсредовые конфликты.** Появляются сценарии, где разные типы транспорта пересекаются (переход через дорогу, мост над водой, аэропорт рядом с дорогой).
4. **Масштабируемость архитектуры.** Каждый новый тип — это новый модуль, ядро не меняется.

## Минимальный жизнеспособный продукт с четырьмя типами

1. **Тротуарный слой:** граф из 8–10 узлов, лестница, узкий тротуар, скопление пешеходов, занятый вход.
2. **Дорожный слой:** граф из 10–12 узлов, перекоп, светофор, закрытая полоса.
3. **Воздушный слой:** 2–3 запретные зоны, 2 эшелона.
4. **Водный слой:** граф из 8 узлов, шлюз, разводной мост, мель.
5. **Диспетчер** с четырьмя модулями и единой картой занятости.
6. **10–12 сценариев**, включая минимум один **межсредовый конфликт** (ровер и автомобиль на переходе).
7. **Визуализация** — четыре слоя, разные цвета для разных типов транспорта.

Это уже полноценная **мультимодальная диспетчерская система**, которая демонстрирует понимание городской логистики, архитектурного проектирования и алгоритмического мышления.
