## 1. Общие сведения о МДС

### 1.1. Назначение

Мультимодальная диспетчерская система (МДС) — программный комплекс для **согласования маршрутов автономного городского транспорта** четырёх типов:

- **Тротуарные роверы** — доставка по тротуарам и пешеходным зонам;
- **Беспилотные автомобили** — доставка по проезжей части;
- **Воздушные дроны** — доставка по воздушным коридорам;
- **Водные суда** — доставка по фарватерам и каналам.

Система **не управляет** транспортом. Она принимает заявки на маршрут, проверяет их на конфликты с препятствиями и другими маршрутами, согласовывает или отклоняет, ведёт карту занятости, принимает телеметрию и актуализирует маршруты в реальном времени.

### 1.2. Основные функции

| Функция | Описание |
|---|---|
| Регистрация клиентов | Приём и учёт служб доставки, магазинов |
| Приём заявок | Регистрация запросов на маршрут |
| Проверка маршрута | Анализ на препятствия и конфликты |
| Согласование | Решение: одобрено / одобрено с изменениями / отклонено |
| Карта занятости | Учёт всех согласованных маршрутов |
| Приём телеметрии | Получение данных о движении от клиентов |
| Детект отклонений | Сравнение фактического движения с планом |
| Актуализация маршрутов | Обновление временных окон в реальном времени |
| Визуализация | Карта города, временные окна, метрики |
| Журналирование | Запись всех событий системы |

### 1.3. Термины и определения

| Термин | Определение |
|---|---|
| **Клиент** | Служба доставки, магазин, зарегистрированный в системе |
| **Заявка** | Запрос на согласование маршрута |
| **Маршрут** | Последовательность точек (waypoints) |
| **Коридор** | Полоса пространства, занимаемая транспортом |
| **Временное окно** | Интервал, в течение которого маршрут активен |
| **Телеметрия** | Данные от клиента о движении транспорта |
| **Отклонение** | Расхождение между планом и фактом |
| **Препятствие** | Объект, блокирующий или замедляющий движение |
| **Карта занятости** | Структура данных с активными маршрутами |

## 4. Руководство пользователя (клиента)

### 4.1. Получение доступа

1. Обратитесь к администратору системы.
2. Предоставьте: название организации, ИНН, контактное лицо, список транспортных средств.
3. Получите **API-ключ** и **client_id**.
4. Сохраните их в защищённом месте.

### 4.2. Подача заявки на маршрут

**Эндпоинт:** `POST /api/v1/requests`

**Заголовки:**
```
Content-Type: application/json
X-API-Key: <ваш_api_ключ>
```

**Тело запроса:**
```json
{
  "request_id": "REQ-2025-001",
  "client_id": "pizza_shop_01",
  "transport_type": "sidewalk_rover",
  "waypoints": [
    {"x": 10, "y": 20, "z": 0},
    {"x": 30, "y": 35, "z": 0},
    {"x": 50, "y": 50, "z": 0}
  ],
  "departure_time": "2025-06-01T14:00:00Z",
  "cargo_weight": 2.5,
  "vehicle_params": {
    "width": 0.9,
    "max_slope": 15
  }
}
```

**Ответ (успех):**
```json
{
  "request_id": "REQ-2025-001",
  "status": "approved",
  "reason": "Маршрут свободен",
  "route_id": "R-001",
  "conflicts": []
}
```

**Ответ (с изменениями):**
```json
{
  "request_id": "REQ-2025-001",
  "status": "approved_with_changes",
  "reason": "Объезд препятствия stairs_1",
  "route_id": "R-002",
  "conflicts": ["stairs_1"]
}
```

**Ответ (отказ):**
```json
{
  "request_id": "REQ-2025-001",
  "status": "rejected",
  "reason": "Маршрут невозможен: коридор перегружен",
  "conflicts": ["OVERLOAD"]
}
```

### 4.3. Типы транспорта и параметры

| Тип              | Обязательные параметры | Описание               |
| ---------------- | ---------------------- | ---------------------- |
| `sidewalk_rover` | `width` (м)            | Тротуарный ровер       |
| `autonomous_car` | `height`, `mass`       | Беспилотный автомобиль |
| `aerial_drone`   | `max_alt`, `payload`   | Воздушный дрон         |
| `water_vessel`   | `draft`, `height`      | Водный катер           |

### 4.4. Отправка телеметрии

**Эндпоинт:** `POST /api/v1/telemetry`

**Частота:** каждые 1–5 секунд (рекомендуется 2 секунды).

**Тело запроса:**
```json
{
  "schema_version": "1.0",
  "client_id": "pizza_shop_01",
  "batch_id": "batch-2025-06-01-14-00-001",
  "sent_at": "2025-06-01T14:00:05Z",
  "vehicles": [
    {
      "vehicle_id": "rover_007",
      "route_id": "R-001",
      "transport_type": "sidewalk_rover",
      "timestamp": "2025-06-01T14:00:00Z",
      "position": {"x": 12.5, "y": 34.2, "z": 0.0},
      "speed": 1.4,
      "status": "moving",
      "progress": 0.35,
      "eta": "2025-06-01T14:12:00Z",
      "battery": 78.5,
      "alerts": []
    }
  ]
}
```

**Ответ:**
```json
{
  "status": "accepted",
  "batch_id": "batch-2025-06-01-14-00-001",
  "processed_vehicles": 1,
  "warnings": []
}
```

### 4.5. Статусы транспорта

| Статус    | Значение                    | Реакция диспетчера       |
| --------- | --------------------------- | ------------------------ |
| `moving`  | Движется по маршруту        | Обновление позиции       |
| `waiting` | Ожидает (светофор, очередь) | Продление окна           |
| `blocked` | Заблокирован                | Продление + reroute      |
| `arrived` | Прибыл                      | Освобождение коридора    |
| `lost`    | Потеряна связь              | Консервативное продление |

### 4.6. Алерты и события

| Код               | Severity | Действие клиента       |
| ----------------- | -------- | ---------------------- |
| `BLOCKED`         | high     | Сообщить о препятствии |
| `BATTERY_LOW`     | medium   | Запланировать возврат  |
| `ROUTE_DEVIATION` | medium   | Проверить навигацию    |
| `CARGO_TEMP_HIGH` | high     | Ускорить доставку      |
| `COLLISION_RISK`  | critical | Экстренная остановка   |

### 4.7. Типовые сценарии

**Сценарий 1: Обычная доставка**
1. Отправить заявку → получить `route_id`.
2. Начать движение, отправлять телеметрию каждые 2 сек.
3. При отклонении от плана — получить уведомление.
4. По прибытии — отправить `status: "arrived"`.

**Сценарий 2: Обнаружено препятствие**
1. В поле `alerts` отправить `["BLOCKED"]`.
2. В `status` указать `blocked`.
3. Дождаться решения диспетчера (продление окна, новый маршрут).

**Сценарий 3: Опоздание**
1. Диспетчер сам продлит окно по телеметрии.
2. Клиент получит уведомление в логе событий.

## 6. Формат телеметрии

### 6.1. Схема пакета

```json
{
  "schema_version": "1.0",
  "client_id": "string",
  "batch_id": "string",
  "sent_at": "ISO8601",
  "vehicles": [
    {
      "vehicle_id": "string",
      "route_id": "string",
      "transport_type": "enum",
      "timestamp": "ISO8601",
      "position": {"x": float, "y": float, "z": float},
      "speed": float,
      "heading": float,
      "status": "enum",
      "progress": float,
      "eta": "ISO8601",
      "battery": float,
      "cargo": {"weight": float, "type": "enum"},
      "alerts": ["string"]
    }
  ]
}
```

### 6.2. Ограничения

| Поле           | Ограничение               |
| -------------- | ------------------------- |
| `vehicles`     | 1–1000 элементов          |
| `speed`        | 0–100 м/с                 |
| `progress`     | 0.0–1.0                   |
| `battery`      | 0–100%                    |
| `cargo.weight` | 0–100 кг                  |
| `batch_id`     | уникальный в течение часа |

### 6.3. Валидация

Система проверяет:
1. Схему JSON (Pydantic).
2. Регистрацию клиента.
3. Принадлежность маршрута клиенту.
4. Свежесть пакета (< 60 сек).
5. Уникальность `batch_id`.
6. Монотонность `timestamp`.

При нарушении — пакет отклоняется с кодом 422 и списком ошибок.

## 7. API-справочник

### 7.1. Эндпоинты

| Метод  | Путь                         | Назначение                 |
| ------ | ---------------------------- | -------------------------- |
| POST   | `/api/v1/requests`           | Подача заявки              |
| GET    | `/api/v1/requests/{id}`      | Статус заявки              |
| DELETE | `/api/v1/requests/{id}`      | Отмена заявки              |
| POST   | `/api/v1/telemetry`          | Отправка телеметрии        |
| GET    | `/api/v1/routes/{id}`        | Информация о маршруте      |
| GET    | `/api/v1/routes/{id}/status` | Текущий статус             |
| GET    | `/api/v1/obstacles`          | Список препятствий         |
| GET    | `/api/v1/health`             | Проверка работоспособности |
| WS     | `/ws/telemetry`              | WebSocket-канал телеметрии |

### 7.2. Аутентификация

Все запросы требуют заголовок:
```
X-API-Key: <ваш_ключ>
```

При отсутствии или неверном ключе — `401 Unauthorized`.

### 7.3. Ограничения скорости

- По умолчанию: 60 запросов в минуту на клиента.
- При превышении — `429 Too Many Requests` с заголовком `Retry-After`.

## 8. Обработка ошибок и коды ответов

### 8.1. HTTP-коды

| Код | Значение               | Действие клиента        |
| --- | ---------------------- | ----------------------- |
| 200 | Успех                  | —                       |
| 201 | Создано                | —                       |
| 202 | Принято (телеметрия)   | —                       |
| 400 | Неверный запрос        | Исправить JSON          |
| 401 | Не авторизован         | Проверить API-ключ      |
| 403 | Доступ запрещён        | Проверить client_id     |
| 404 | Не найдено             | Проверить route_id      |
| 409 | Конфликт               | Повторить позже         |
| 422 | Ошибка валидации       | Исправить поля          |
| 429 | Слишком много запросов | Подождать               |
| 500 | Внутренняя ошибка      | Сообщить администратору |
| 503 | Сервис недоступен      | Повторить позже         |

### 8.2. Формат ошибки

```json
{
  "error": "validation_failed",
  "message": "Пакет телеметрии содержит ошибки",
  "details": [
    {"field": "vehicles[0].progress", "error": "must be <= 1.0"},
    {"field": "vehicles[0].timestamp", "error": "must be timezone-aware"}
  ],
  "request_id": "req-abc123"
}
```

### 8.3. Типовые ошибки

| Ошибка                    | Причина                         | Решение                    |
| ------------------------- | ------------------------------- | -------------------------- |
| `client_id mismatch`      | client_id не совпадает с ключом | Проверить поля             |
| `route not approved`      | Маршрут не согласован           | Подать заявку заново       |
| `batch already processed` | Дубликат batch_id               | Использовать уникальные ID |
| `stale packet`            | Пакет старше 60 сек             | Отправлять вовремя         |
| `overload`                | Коридор перегружен              | Сдвинуть вылет             |

## 9. Мониторинг и метрики

### 9.1. Ключевые метрики

| Метрика                        | Формула                     | Норма             |
| ------------------------------ | --------------------------- | ----------------- |
| **Задержка телеметрии**        | `receive_time - sent_at`    | < 5 сек           |
| **Частота отклонений**         | `deviations / packets`      | < 10%             |
| **Процент согласований**       | `approved / total_requests` | > 80%             |
| **Среднее время согласования** | `avg(check_duration)`       | < 100 мс          |
| **Загруженность слоя**         | `active_routes / capacity`  | < 70%             |
| **Количество reroute**         | `reroutes_requested`        | < 5% от маршрутов |

## 12. Безопасность

### 12.1. Аутентификация и авторизация

- API-ключи генерируются с использованием `secrets.token_urlsafe(32)`.
- Ключи хранятся в виде хешей (bcrypt).
- Ротация ключей: раз в 90 дней.
- При компрометации — немедленный отзыв.

### 12.2. Транспортная безопасность

- HTTPS обязателен в продакшне.
- WSS для WebSocket.
- TLS-сертификат: Let's Encrypt.

### 12.3. Валидация входных данных

- Все данные проходят Pydantic-валидацию.
- Отклоняются пакеты с нереалистичными значениями.
- Ограничение размера тела запроса: 1 МБ.
- Санитизация всех строковых полей.

### 12.4. Ограничение скорости

- По умолчанию: 60 запросов в минуту на клиента.
- Для телеметрии: 30 пакетов в минуту.
- При превышении — блокировка на 60 секунд.

### 12.5. Аудит

Все действия записываются в журнал:
- Кто (client_id);
- Когда (timestamp);
- Что (тип операции);
- Результат (успех/ошибка);
- IP-адрес.

### 12.6. Рекомендации

- Не передавать API-ключи в открытом виде.
- Использовать переменные окружения.
- Регулярно обновлять зависимости.
- Мониторить подозрительную активность.
