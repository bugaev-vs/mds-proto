## Имитатор системы геопозиционирования (GPS, ГЛОНАСС) - Описание программы распознавания QR-сетки в реальном времени
## Назначение

Программа предназначена для **автоматического контроля правильности сборки QR-поля 20×20** (лист 1×1 метр, склеенный из A4-страниц) с помощью веб-камеры в реальном времени. Она распознаёт QR-коды, наложенные на физический лист, сопоставляет их с идеальной геометрической сеткой, отображает результат поверх видеопотока и сигнализирует о проблемных ячейках.

## Основные возможности

1. **Распознавание QR-кодов** через веб-камеру в реальном времени (библиотека OpenCV, `QRCodeDetector` с поддержкой alignment-маркеров).
2. **Определение координат ячейки** непосредственно из текста QR-кода — каждый код содержит имя вида `A1`, `B7`, `T20`, где буква задаёт строку, а число — столбец.
3. **Построение перспективной сетки 20×20** на кадре: по четырём крайним распознанным ячейкам вычисляется гомография, которая «приклеивает» идеальную сетку к физическому листу даже при наклоне и искажениях камеры.
4. **Кэширование распознанных ячеек** — единожды прочитанный QR-код сохраняется в памяти и отображается даже тогда, когда он ушёл из кадра или был закрыт другим кодом.
5. **Классификация состояния каждой ячейки** видимой области на три категории:
   - **OK** — QR распознан, его координаты совпадают с координатами ячейки;
   - **ЗАКРЫТО (covered)** — в ячейке лежит чужой QR-код, координаты которого не совпадают с координатами ячейки (признак того, что правильный код перекрыт);
   - **ПУСТО (empty)** — QR не обнаружен ни сейчас, ни в кэше.
6. **Визуальная индикация** прямо на кадре:
   - распознанные ячейки обводятся зелёным контуром и подписываются;
   - закрытые ячейки выделяются оранжевым контуром;
   - пустые ячейки перечёркиваются красными диагоналями.
7. **Боковая панель** с обновляемым в реальном времени списком проблемных ячеек:
   - секция «ЗАКРЫТЫ» со строками вида `A3 <- B2` («в ячейке A3 лежит QR от B2»);
   - секция «ПУСТО» с перечислением имён ячеек, где код так и не был найден.

## Архитектура и ключевые алгоритмы

### 1. Захват видео
Камера открывается через `cv2.VideoCapture` с бэкендом `CAP_DSHOW` (оптимально для Windows). Разрешение по умолчанию — 1280×720.

### 2. Детекция и декодирование
Метод `detectAndDecodeMulti` за один проход возвращает:
- массив распознанных строк (`decoded_info`),
- массив четырёхугольников (`points`) — по 4 угла на каждый QR.

Для каждого результата выполняется парсинг имени ячейки регулярным выражением `([A-T])(\d{1,2})`.

### 3. Построение гомографии
Из множества видимых ячеек выбираются четыре «угловые» — верх-лево, верх-право, низ-право, низ-лево (по минимуму/максимуму `row` и `col`). Их центры служат исходными точками для `cv2.getPerspectiveTransform`. Целевые точки — идеальные координаты этих же ячеек в «мировой» системе (где 1.0 = сторона одной ячейки).

Полученная гомография `H` преобразует мировые координаты `(col, row)` в пиксельные `(x, y)` кадра. Для устранения дрожания применяется экспоненциальное сглаживание: `H_smooth = α·H_smooth + (1−α)·H`, где `α` настраивается (по умолчанию 0.7).

### 4. Классификация ячеек
Для каждой ячейки видимой области:
- вычисляется её четырёхугольник в кадре через `w2s(col, row)`;
- проверяется наличие текста в кэше;
- для каждого видимого QR проверяется, попадает ли его **центр** внутрь данной геометрической ячейки, и совпадают ли при этом координаты QR с координатами ячейки. Если нет — фиксируется перекрытие.

### 5. Отрисовка
Кадр дополняется справа чёрной панелью шириной `PANEL_W` (по умолчанию 340 px). В левой части рисуются сетка, контуры ячеек, подписи и перечёркивания; в правой — секции со списком проблемных ячеек. Списки сортируются по `(row, col)`, длинные перечисления «ПУСТО» переносятся по строкам с ограничением по ширине.

### 6. Кэш и его устаревание
Словари `cell_text`, `cell_quad`, `cell_age` хранят последнее известное состояние каждой ячейки. Параметр `CACHE_TTL` управляет временем жизни записи:
- `CACHE_TTL = 0` — помнить бесконечно (рекомендуется, чтобы «залипали» уже прочитанные ячейки);
- `CACHE_TTL > 0` — число кадров, после которого запись удаляется, если ячейка не видна.

## Управление

| Клавиша | Действие |
|---|---|
| `ESC` или `Q` | выход из программы |
| `R` | сброс кэша распознанных ячеек и гомографии |

## Настройки (константы в начале кода)

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `COLS`, `ROWS` | размер сетки | 20 × 20 |
| `CAM_INDEX` | индекс камеры | 0 |
| `FRAME_W`, `FRAME_H` | разрешение захвата | 1280 × 720 |
| `ALPHA` | коэффициент сглаживания гомографии | 0.7 |
| `CACHE_TTL` | время жизни кэша в кадрах | 0 (бесконечно) |
| `PANEL_W` | ширина боковой панели | 340 px |

## Требования и установка

- Python 3.8+
- Зависимости:
  ```
  pip install opencv-contrib-python numpy
  ```
- Операционная система: Windows (используется `CAP_DSHOW`; для других ОС достаточно убрать флаг).

## Ограничения

- QR-код, полностью перекрытый другим кодом, физически не может быть прочитан — программа зафиксирует это как `covered` и покажет, какой именно код лежит сверху.
- Для построения гомографии требуется минимум 4 распознанные ячейки; до этого момента сетка и панель анализа не отображаются.
- При сильном шуме детектора возможны ложные срабатывания «перекрытия», если QR частично выходит за пределы своей ячейки; чувствительность регулируется способом проверки попадания центра (можно ужесточить, проверяя весь квад).

## Сценарий использования

1. Запустить программу, навести камеру на лист так, чтобы в кадр попадали минимум 4 ячейки по углам видимой области.
2. Убедиться, что сетка «села» на лист, а ячейки подписались своими именами.
3. Медленно проводить камерой по листу — все распознанные ячейки накапливаются в кэше.
4. Смотреть на правую панель: в секции «ЗАКРЫТЫ» появятся ячейки, в которых лежит не тот QR; в секции «ПУСТО» — ячейки, где кода нет вовсе.
5. Найденные проблемные места исправить вручную, повторно проверить камерой.
