ДОКЛАД НА ЗАЩИТУ ШКОЛЬНОГО ПРОЕКТА
«Мультимодальная диспетчерская система управления беспилотным транспортом»

================================================================================

СЛАЙД 1 (0:30 мин): ТИТУЛЬНЫЙ
Уважаемые члены комиссии, здравствуйте!

Рад представить вам школьный проект «Мультимодальная диспетчерская система управления беспилотным транспортом» (МДС).

Моя тема посвящена созданию системы для согласования маршрутов автономного городского транспорта четырёх типов: тротуарных роверов, беспилотных автомобилей, воздушных дронов и водных катеров.

Система разрабатывается на Python с использованием Flask, Pydantic, Shapely и других современных библиотек.

================================================================================

СЛАЙД 2 (1:00 мин): АКТУАЛЬНОСТЬ ПРОЕКТА
Почему этот проект важен?

В крупных городах уже используются автономные транспортные средства: роверы доставляют заказы, развиваются беспилотные такси, внедряются дроны служб доставки.

Однако растёт не только количество транспорта — растёт и разнообразие маршрутов. Клиент выбирает способ доставки: курьером? ровером? дроном? катером?

Это создаёт сложную логистическую задачу. Без единого координатора возможны столкновения, взаимные блокировки и нарушения запретных зон.

Целевая функция клиента для оптимизации:
min V(x)/C(x) при условиях T(x) ≤ Tmax и C(x) ≤ Cmax

СЛАЙД 3 (1:00 мин): ПРОБЛЕМА СУЩЕСТВУЮЩИХ ПРАВИЛ ПДД
Почему правил ПДД недостаточно для АТС?

1. ПДД распространяются только на наземный транспорт
2. Ширина тротуаров не всегда позволяет движение АТС без помех пешеходам
3. Законы об АТС находятся на стадии разработки
4. Штат ГАИ рассчитан для обычного транспорта, не покрывает рост АТС
5. ДТП на тротуарах с моторизированной техникой растут
6. АТС не умеют автоматически интерпретировать сигналы регулировщика
7. Рост риска незаконного использования АТС требует оперативного контроля

================================================================================

СЛАЙД 4 (1:00 мин): ЗАДАЧИ МДС
Мультимодальная диспетчерская система решает пять задач:

1. СНИЖЕНИЕ СРОКОВ ДОСТАВКИ — выбор оптимального маршрута с учётом ситуации

2. БЕЗОПАСНОСТЬ — не допускать столкновений и появления в запретных зонах

3. ПОВЫШЕНИЕ ЭФФЕКТИВНОСТИ — распределение маршрутов без перегрузки коридоров

4. КОНТРОЛЛИРУЕМОСТЬ — актуальная информация о загруженности для городских служб

5. ОБРАТНАЯ СВЯЗЬ ОПЕРАТОРУ — возможность менять маршруты с учётом ремонтов, мелей

СЛАЙД 6 (1:00 мин): ЦИКЛ ДИСПЕТЧЕРИЗАЦИИ МДС
Оператор АТС → Заявка в МДС → Проверка → Согласование → Движение АТС → Телеметрия → Актуализация

Ключевые этапы:
1. Оператор подаёт заявку (точки, маршрут, тип транспорта)
2. МДС проверяет конфликты и препятствия
3. Решение: согласовано / с изменениями / отклонено
4. Маршрут вносится в карту занятости
5. Оператор отправляет телеметрию (позиция, статус, ETA)
6. МДС актуализирует информацию и корректирует маршруты

================================================================================

СЛАЙД 7 (1:00 мин): АРХИТЕКТУРА СИСТЕМЫ
Компоненты МДС:

• CityMap — карта препятствий (лестницы, шлюзы, запретные зоны)
• Dispatcher — ядро системы (приём заявок, проверка, согласование)
• OccupancyMap — карта занятости маршрутов по времени (4 слоя)
• Detector — детект отклонений от плана
• Validator — валидация телеметрии клиентов
• Visualizer — визуализация карты и метрик

Карта занятости — четыре независимых слоя:
• sidewalk — тротуарные роверы
• road — беспилотные автомобили
• air — воздушные дроны
• water — водные катера

СЛАЙД 8 (1:00 мин): СТРУКТУРЫ ДАННЫХ И ФОРМАТЫ
Типы транспорта (Enum): SIDEWALK_ROVER, AUTONOMOUS_CAR, AERIAL_DRONE, WATER_VESSEL

Статусы решения (Enum): APPROVED, APPROVED_WITH_CHANGES, REJECTED, PENDING

Waypoint — точка маршрута с координатами x, y, z и меткой препятствия

RouteRequest — заявка содержит waypoints, время вылета, параметры ТС:
Для ровера: width=0.9 м, max_slope=15°
Для дрона: max_alt=120 м, payload=5 кг

JSON-формат телеметрии:
{
  "client_id": "pizza_shop_01",
  "batch_id": "batch-001",
  "vehicles": [{
    "vehicle_id": "rover_007",
    "route_id": "R-001",
    "position": {"x": 12.5, "y": 34.2},
    "status": "moving",
    "progress": 0.35,
    "eta": "2025-06-01T14:12:00Z"
  }]
}

СЛАЙД 9 (1:00 мин): ТЕХНОЛОГИИ И МАСШТАБИРУЕМОСТЬ
Технологический стек:

• Python 3.10+ — основной язык
• Flask — веб-сервер и REST API
• Pydantic — валидация данных (схема JSON)
• Shapely — геометрические расчёты (пересечения, полигоны)
• Networkx — графы маршрутов
• Matplotlib — визуализация (карты, графики Ганта, диаграммы)
• WebSocket — реальное время

Принцип масштабируемости:
"Новый тип транспорта = новый модуль проверки, ядро не меняется"

Сложность растёт линейно, а не экспоненциально.
